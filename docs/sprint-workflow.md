# Sprint 工作流程

## 完整流程圖

```
董事會下達產品方向
       ↓
┌─── Phase 0: 產品提案 ───┐
│  CEO 評估收入模式        │
│  通過 → 進入 Phase 1    │
│  不通過 → 打回重提       │
└─────────────────────────┘
       ↓
┌─── Phase 1: Sprint Contract ───┐
│  PM 小陳 寫 PRD               │
│  QA 小趙 制定評分標準          │
│  雙方協商「什麼算完成」        │
│  CEO 審核批准                  │
└────────────────────────────────┘
       ↓
┌─── Phase 2: Implementation ───┐
│  CTO 小李 拆解技術任務         │
│  工程師 小林 實作前後端        │
│  支付專家 小錢 實作支付功能    │
│  完成後提交交接文件            │
└────────────────────────────────┘
       ↓
┌─── Phase 3: Evaluation ───────┐
│  QA 小趙 獨立測試             │
│  按 Sprint Contract 逐項打分  │
│  產出評分報告                  │
└────────────────────────────────┘
       ↓
┌─── Phase 4: Ship or Iterate ──┐
│  ≥ 4.0 → 上線                 │
│  3.5-4.0 → 小修後上線         │
│  < 3.5 → 打回 Phase 2 重做   │
└────────────────────────────────┘
```

## Phase 0: 產品提案評估

CEO 收到董事會的產品方向後，必須回答六個問題：

1. **錢從哪裡來？** — 付費用戶是誰？為什麼願意付錢？
2. **定價** — 月費多少？免費版 vs 付費版？
3. **付費轉換點** — 用戶在什麼時刻想付錢？
4. **市場規模** — 多少潛在付費用戶？
5. **成本** — API 調用成本？毛利是否為正？
6. **競品** — 差異化是什麼？

六個問題都答不出來就不做。

## Phase 1: Sprint Contract

### PM 的 PRD 必須包含：
- 產品名稱 + 一句話描述
- 目標用戶（具體的人）
- 用戶痛點
- 核心功能清單（MVP 最小集）
- 用戶流程圖（從進入到付費）
- 定價（TWD）
- 競品分析
- 成本估算

### QA 的評分標準必須包含：
- 每個功能的驗收條件
- 每個維度的 1/3/5 分定義
- 測試方法（自動化 or 手動）

### 協商規則：
- PM 不能單方面降低標準
- QA 不能提出超出 PRD 範圍的要求
- 有爭議由 CEO 裁決

## Phase 2: Implementation

### CTO 拆解原則：
- 每個任務不超過 4 小時工作量
- 前後端可以並行
- 支付相關任務必須分配給支付專家小錢

### 交接文件必須包含：
```markdown
## Sprint 交接文件
### 實作了什麼
- [功能清單]

### 修改了哪些文件
- [文件列表]

### 如何測試
- [本地啟動方式]
- [測試帳號]

### 已知問題
- [問題列表]

### 部署方式
- [部署命令]
```

## Phase 3: Evaluation

### QA 測試原則：
- **獨立部署**，不使用 Generator 的測試環境
- **從零開始**測試，不依賴 Generator 的測試結果
- **像真實用戶一樣**使用產品
- **偏向懷疑** — 預設沒通過，看到證據才通過

### 測試範圍：
1. 功能測試 — 所有 Sprint Contract 裡的功能
2. 付費測試 — 完整走一遍付費流程（ECPay 測試環境）
3. 安全測試 — XSS、CSRF、SQL injection
4. 響應式測試 — 手機 + 桌面
5. i18n 測試 — 繁體中文顯示

## Phase 4: 決策矩陣

| 總分 | 決定 | 動作 |
|---|---|---|
| ≥ 4.0 | 上線 | 部署到 Cloudflare Pages |
| 3.5-4.0 | 小修 | 只修關鍵問題，不加新功能 |
| < 3.5 | 重做 | 打回 Phase 2，保留評分報告作為參考 |
| 連續兩次 < 3.0 | 砍掉 | 放棄這個產品方向 |
